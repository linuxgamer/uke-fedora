| B25 | P1 | Keep the Pogo keyboard scanning after boot | done | The keyboard worked from boot and then went silent a few minutes in while the MCU kept streaming accelerometer data. Ruled out on the device: no `D` state task and an empty `sysrq-w` list (so no `conn_mutex` deadlock), `input_match_device_id()`'s `bitmap_subset(id->swbit, dev->swbit, SW_MAX)` never matching the two `xiaomi_hall` children (they expose `0x2` and `0x1` separately, never `0x3`), a stuck `suspended` flag, and an MCU refusing to answer (GPIO 116 kept counting under key presses). The MiAuth handshake was the cause: the driver answers `0x24` with `MIAUTH`, `0x31` with `key_meta` plus a challenge, and waits for a token on `0x32`, but there is no token source on Linux - the Android AIDL HAL `vendor.xiaomi.hardware.keyboardnanoapp_aidl-service` owns it, and `nanosic-authd` can only send sixteen zero bytes, so the MCU re-challenges about once a minute and eventually stops scanning keys. The OEM `nanosic_driver.ko` has no MiAuth path at all. Fixed by leaving the handshake alone unless `mi_auth=1` is passed on load (kernel `5c87b0f`) and by no longer enabling `nanosic-authd` at boot (umbrella `4dedb5c`, gitlink `e385460`); the two silent input-drop paths now log. |
