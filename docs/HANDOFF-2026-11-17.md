## Build-platform changes (all in `main`)

The submodule repos are upstream-owned, so CI applies asserted overlays at build
time. Each replacement fails the build if its anchor drifts.

### `maint/prepare-ci-tree.py` (base overlay)

- OEM firmware count 74 → 75 (verify-oem-rpm + audit-rootfs)
- container selection via `UKE_CONTAINER`
- install the OEM data RPM in the main transaction
- sudo for the COPR repo file write
- touch firmware installed to the kernel-requested path
  (`/usr/lib/firmware/qcom/uke/touch/...`) in addition to `/var/lib/uke-touch`
- audio assets: `fs19xx.fsm`, `asound.state`, WirePlumber speaker priority
- GPU: drop `msm.separate_gpu_kms=1` from cmdline and comment the modprobe option
- modules: `MODULE_SIG_FORCE` off, `LOCK_DOWN_KERNEL_FORCE_INTEGRITY` off, signing kept
- stage patched `tests/kernel-hardening-config-contract.sh` from the worktree
  (SRPM archives HEAD, so the Makefile copies tests over the archive)
- root account: `root:fedora` + unlock (TTY login works)
- KDE + GDM: install GDM in a separate transaction after removing the
  `display-manager.service` alias, mask `sddm`/`plasmalogin`/`plasma-setup`,
  pre-create **uke:fedora** (wheel, bash), AccountsService `Session=plasma`,
  `InitialSetupEnable=false`, enable `gdm.service`, default `graphical.target`

- first-boot storage gate for DM units changed `Requires=` → `Wants=`

### `maint/prepare-ci-fallback.py` (video + zram)

## Userspace / kernel contents

- Desktop: KDE Plasma, Wayland session `plasma`, GDM login (no autologin)
- Accounts: `uke` / `fedora` (wheel), `root` / `fedora`
- zram: 6 GiB ceiling via `systemd-zram-generator`
- Video: Iris DT overlay + `qcom/uke/vpu30_2v.mbn` + `uke-vaapi-v4l2`
- GPU: single KMS (no `separate_gpu_kms`)
- Modules: unsigned `insmod` allowed (no forced sig/integrity), vermagic must match 7.3.1-106
- KVM: host config + QEMU/libvirt/OVMF packages; runtime `/dev/kvm` depends on EL2

## Known risks / unverified

- **Hardware boot not tested.** Biggest risk is the Iris video DT overlay; if it
  probes badly the failure is a hang/black screen before userspace.
- GDM starts after rootfs mount; failure here is a black screen with console
  still on tty2–6 (`root`/`fedora` works).
- `/dev/kvm` will likely be absent unless the boot chain enters at EL2; config
  alone does not grant EL2. The repo has an experimental EL2 entry that is
  deliberately not built (`admit-el2-profile.sh` refuses it).
- VA-API decode path is untested; no `/dev/video*` verification yet.
- Splash/quiet not in this image (`loglevel=7`, no Plymouth).
- Boot image has **no initramfs**, so all boot-critical drivers must be built-in;
  early boot logs are only on the framebuffer/console.

## NPU side work (Android, separate from the Fedora image)

- Hexagon v73 stack in `/data/local/tmp/qwen-npu` (llama.cpp + `ggml-hexagon`),
  HTP0, `-ngl 99`, `-fa off`, `GGML_HEXAGON_MM_SELECT=1`.
- Qwen3-0.6B Q4_0: 45 t/s single; 56.8 t/s aggregate at 16 parallel slots.
- Qwen3-1.7B Q4_0: ~20 t/s single; 33.6 t/s aggregate at 8 slots.
- HMX path (`MM_SELECT=0`) is slower and numerically broken on v73.
- Phi-4-mini Q4_0 (3.8B): 25.6 t/s prompt / 12.4 t/s generation at 512 ctx;
  ~2.55 GB pinned (2.33 GB weights + KV + host).
- zram test: ext4 on zram1, Qwen3-1.7B copied in; compression ~1.004× (none),
  same ~19–20 t/s, no benefit. zram1 removed afterwards.
- Simple zram hot-add: **read** `/sys/class/zram-control/hot_add` (it is 0400;
  writing fails). Needs SELinux permissive for root writes; restored after.
